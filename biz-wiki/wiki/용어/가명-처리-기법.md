# 가명 처리 기법

원본 데이터를 알아볼 수 없게 바꾸는 방법들. 결합에서는 원 데이터를 최대한 유지하려 하므로 암호화와 삭제 위주로 쓴다.

## 정의
- 기본 관점: 식별 가능한 정보는 모두 개인정보로 본다. 1차로 알아보지 못하게 바꾸고(가명), 더 나아가 그룹핑 등으로 더 알아볼 수 없게 하는 것이 익명화의 목표. (출처: 김영권 18:04)
- 주요 기법 (출처: 김영권 18:04~19:07)
  - 삭제: 분석에 필요 없는 식별 정보(전화번호 등)는 지운다
  - 암호화: ID 등은 암호화
  - 변환: 생년월일 → 연도·월만 남겨 연령 계산
  - 범주화: 연령을 5세 단위 구간 등으로 묶음
  - 치환: 분포가 비슷한 다른 값으로 바꾸는 방법도 있음
  - 지역: 시군구, 우편번호 수준으로 가공

## 헷갈리는 점
- 결합하는 입장에서는 원 데이터를 유지하길 원하므로, 대부분 가명 처리(암호화) 위주로 한다. (출처: 김영권 18:04)
- 성별·연령은 분석에 쓰일 수 있어 남기는 경우가 있다. 원문 "성별이나 연령은 리콜이 가능" — 의미 확인 필요. [확인필요] (출처: 김영권 19:07)
- 외부 제공 시 최소 기준은 [[비식별-처리-그라운드룰]]을 따른다.
- 결합 시 전문기관은 처리 방법에 관여하지 않고 가이드만 준다. (출처: 김영권 19:07)

## 사용 예
"생년월일 중에서 연도나 월 정도만 가지고 연령만 계산하면 크게 문제가 없기 때문에" (출처: 김영권 19:07)

## 정보보호 설명: 당사가 주로 쓰는 기법과 l-다양성
- 교육 장표에 나온 당사의 주요 처리 항목: 샘플링, 불필요한 데이터 삭제, k-익명성, 노이즈 추가 등 (순서는 언급 없음). (출처: 정보보호교육 14:41) [사용자 승인 2026-11-12]
- 보통 k-익명성을 쓰고 l-다양성·t-근접성까지 하는 경우는 거의 없다. 다만 **준식별자 속성을 행 안에 넣지 않고 가로로 펼쳐 넣으면** 평가위원이 l-다양성도 보는 경우가 있어 [[적정성-평가]]에서 걸릴 수 있다. (출처: 정보보호교육 14:41) [사용자 승인 2026-11-12]
- 사례: [[홍진규]] 프로 건(원문 "진규 프로그램", 명단 대조)이 l-다양성으로 걸려 재처리했다. (출처: 정보보호교육 14:41) [사용자 승인 2026-11-12]
- 처리 후에는 익명 처리자 또는 가명 처리자가 평가용 기초 자료를 작성한다. 양식은 건마다 조금 다르지만 기본은 표지(수요처 등) + 처리 내용. 샘플은 [[임주환]] 프로에게 받아 본다. (출처: 정보보호교육 14:41) [사용자 승인 2026-11-12]
- 시계열·반복 제공 샘플링 기준은 [[시계열-제공-샘플링]].
