# 관심지역 모니터링 데이터

오픈메이트가 필요한 시점에 공간영역 단위로 집계된 일 단위 카드 소비 데이터를 API로 가져가 과금되고, 지자체 주무관이 오픈메이트 시스템에서 공간영역을 지정해 지역 소비트렌드와 효과를 분석하는 건.

## 개요
- 관심지역 모니터링을 위한 데이터셋이다. (출처: 조윤성 메모 #1) [사용자 승인 2026-11-26]
- 당사 데이터는 [[오픈메이트]]가 만든 시스템에 들어간다. (출처: 조윤성 메모 #1) [사용자 승인 2026-11-26]
- **제공 방식**: 데이터의 시간 단위는 일 단위다. 다만 매일 보내는 방식이 아니라, **필요한 시점에 오픈메이트가 레이아웃대로 특정 공간의 데이터를 가져가는** 방식이다. (출처: 확인필요-답변-2026-11-26 조윤성 #2) [사용자 승인 2026-11-26]
  - 처음 설명은 "일단위로 실시간 데이터가 전송"이었고(출처: 조윤성 메모 #1), 같은 날 위처럼 보충·정정했다.
- **제공 단위와 경로**: 오픈메이트는 데이터를 **가맹점 단위로 가져가지 않는다.** **공간영역에 따라 집계한 데이터를 API로** 가져간다. (출처: 확인필요-답변2-2026-11-26 조윤성 #1, #2) [사용자 승인 2026-11-26]
- 지자체 주무관이 오픈메이트 시스템에 들어와 공간영역을 잡으면, 제공 데이터가 그 영역 기준으로 집계되어 지역 소비트렌드와 효과분석을 볼 수 있다. (출처: 조윤성 메모 #1) [사용자 승인 2026-11-26]

## 수요 배경
- 관심지역 모니터링을 위한 데이터셋으로, 지자체 주무관이 지역 소비트렌드·효과분석에 쓴다. (출처: 조윤성 메모 #1) [사용자 승인 2026-11-26]
- 구체적인 고객 지자체와 도입 경위는 확인필요.

## 제공 데이터와 수준
레이아웃 출력물(테이블명 "삼성카드 데이터 레이아웃")에 보이는 컬럼 구성. 머리글의 시간적 범위·단위, 제공 주기, 공간적 범위·단위, 정보 유형 칸은 비어 있었다. (출처: 조윤성 메모 #2, #3) [사용자 승인 2026-11-26]

| 묶음 | 컬럼 | 비고 |
|---|---|---|
| 키 | 조회영역구분코드(INQR_TERY_DV_C), 기준일자(APR_DT) | 각각 카드 매출이 발생한 공간적 범위(예시값 형태 "서초상권_1")와 시간적 범위(예시값 형태 "20250925") |
| 가맹점 | 가맹점 한글명, 간판명, 가맹점번호(MRCNO), 좌표 X·Y | 가맹점번호는 **해시 처리한 고유키**. 좌표는 위경도 |
| 소재지 | 시도·시군구·행정동 이름과 코드 | |
| 업종 | 업종코드, 업종명 | |
| 합계 | 총결제합계금액, 총결제합계건수 | |
| 성·연령대 | 남·여 × 8개 연령 구간(20세미만, 20~70대, 80세이상) × 금액비율·건수비율 | 비율값 |
| 시간대 | 06시이하, 06~23시 1시간 단위 × 금액비율·건수비율 | 비율값 |
| 거주지·국적 | 주변거주·외지인·내지인, 국내거주·외국인 × 금액비율·건수비율 | 비율값. 사진이 96번에서 잘려 그 뒤 컬럼은 확인필요 |

(출처: 조윤성 메모 #3) [사용자 승인 2026-11-26]

- 정정: 처음에는 레이아웃의 컬럼 구성만 보고 행 하나를 "조회영역 × 기준일자 × 가맹점"으로 추정했으나(계산, 발언 아님), 실제 제공은 **공간영역 단위로 집계**해 API로 나간다. (출처: 확인필요-답변2-2026-11-26 조윤성 #1, #2) [사용자 승인 2026-11-26]
- 레이아웃에 가맹점 컬럼(가맹점명·간판명·해시 가맹점번호·좌표)이 있는데, 집계 제공에서 이 컬럼들이 어떻게 쓰이는지(집계 전 내부 단계용인지, API 응답에서 빠지는지)는 확인필요.
- 비교(위키 내용 대조, 발언 아님): 공간 집계 단위로 나가므로 가맹점 단위로 내보내는 [[점별-매출-데이터-제공]]과는 제공 단위가 다르다. 다만 근거 라이선스([[기업정보조회업]] 여부)와 제공분류(가명·익명·기타)는 확인필요.

## 계약·금액
- **과금 방식**: 오픈메이트가 특정 공간의 데이터를 가져가면 그 데이터에 대해 과금한다. (출처: 확인필요-답변-2026-11-26 조윤성 #3) [사용자 승인 2026-11-26]
- 단가, 과금 단위(조회 건별·공간별·기간별), 지자체와의 계약 관계는 확인필요.

## 이력(회차별)
- 2026-11 기준 운영 중 ("현재 오픈메이트에게 …"). (출처: 조윤성 메모 #1) [사용자 승인 2026-11-26]

## 쟁점과 결정
- [[경기도]]의 1시간 단위 실시간 소비 데이터 건(출처: 자치구축제미팅 02:36~03:06)과는 **다른 사업**이다. (출처: 확인필요-답변-2026-11-26 조윤성 #1) [사용자 승인 2026-11-26]
- 비교(위키 내용 대조, 발언 아님): 지자체가 공간영역을 직접 잡아 집계하는 방식은 [[지역축제-데이터]]의 축제 반경 분석과 쓰임이 비슷해 보인다.
