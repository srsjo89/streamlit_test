# 데이터사업팀 지식 위키

데이터사업팀의 업무, 절차, 규칙, 사업 이력을 모은 위키. 원본 15건, 페이지 161개. `초안` 표시 페이지는 검수 전 내용이다.

## 업무
- [[AI-플랫폼]] ·초안 — 2026~2027년 담당의 AI 과제. 자연어로 리포트·분석·마케팅 실행까지 할 수 있는 데이터 서비스 플랫폼과 합성 소비자가 중심이다.
- [[LMS-광고]] ·초안 — 당사 회원 중 수신 동의 고객에게 광고 대행사가 가져온 광고를 LMS로 발송하는 업무. 팀 KPI의 약 절반을 2명이 담당한다.
- [[개인사업자-CB]] ·초안 — 당사가 2023년 9월 취득한 개인사업자 신용평가업 라이선스로 하는 사업. 데이터솔루션팀 CB 파트가 맡고, 사업팀 데이터 판매와 깊게 얽혀 있다.
- [[기업정보조회업]] ·초안 — 신용평가 없이 기업 정보만 제공할 수 있는 기업 CB 라이선스. 당사는 2025년 취득했고, 이를 근거로 가맹점별 매출 데이터를 공식적으로 낼 수 있게 됐다.
- [[내부-영업채널-연계]] ·초안 — 지역사업단과 법인영업팀의 KPI에 데이터사업이 들어가 있어, 이들이 고객을 소개해 준다. 현재 신규 고객이 들어오는 주된 통로다.
- [[데이터-외부제공]] ·초안 — 당사 데이터를 외부 고객·기관에 제공하는 업무. 수요 발굴부터 정보 분류, 품의, 비식별 처리, 적정성 평가, 반출, 정산까지 이어진다.
- [[데이터-전문기관]] ·초안 — 금융위원회가 지정한 데이터 전문기관 라이선스로 가명정보 결합을 수행하는 업무. 돈은 되지 않지만 사업 수단·홍보 수단으로 유지하고 있다.
- [[데이터-전송-개발]] ·초안 — 반복적으로 나가는 제공 데이터를 매번 수작업하지 않도록 API나 FTP 자동 전송을 개발하는 업무.
- [[데이터톡]] ·초안 — 데이터솔루션팀이 월 1회 내는 데이터 리포트. 기자들이 기사로 다뤄 데이터 역량 홍보에 도움이 된다.
- [[임베디드-서비스]] ·초안 — 고객이나 사업자에 대한 점수·지수 모델을 만들어 매일 또는 매월 상대 서비스에 넣어 쓰게 하는 B2B 상품. 데이터솔루션팀이 주로 맡는다.
- [[팀-사무국-KPI-관리]] ·초안 — 담당 단위의 KPI·임원 평가 관리와 각종 보고자료 대응을 맡는 사무국 업무. 데이터사업 담당은 [[최원재]] 프로 혼자 한다.

## 프로세스
- [[API-전송-개발-절차]] ·초안 — 데이터 제공을 API·FTP 자동 전송으로 개발하는 절차. 업체와 미리 협의하고 체크리스트를 따른다.
- [[가익명-시스템-DB-접근-신청]] ·초안 — 프로젝트가 생기면 [[가익명-시스템]]에서 프로젝트 전용 DB를 받고 접근 권한을 신청하는 절차.
- [[가익명-시스템-반출-절차]] ·초안 — 외부로 나가는 데이터는 반드시 [[가익명-시스템]]에 올렸다가 내려받아, 등록된 해시와 일치하는 파일만 내보낸다.
- [[데이터-결합-절차]] ·초안 — 데이터 전문기관에서 두 회사 이상의 가명정보를 결합하고 결과를 내보내기까지의 절차.
- [[데이터-외부제공-전체-프로세스]] ·초안 — 수요 발굴부터 정산·개발까지 데이터 외부 제공의 전 단계.
- [[적정성-평가]] ·초안 — 가명·익명 처리된 데이터가 제대로 비식별되었는지 외부 위원이 평가하는 월 1회 내부 절차.
- [[점별-매출-데이터-제공]] ·초안 — 가맹점별 매출(당사 매출 + 추정매출)을 고객에게 내보내는 절차. 2026년 4월부터 공식화됐고, 반드시 사내 CB 파트를 거친다. 고객 반응이 가장 좋은 데이터다.

## 규칙
- [[CB는-다른-회사로-간주]] ·초안 — 당사 [[개인사업자-CB]] 파트(데이터솔루션팀)와 함께 일할 때는 같은 회사로 생각하지 말고, 외부 회사에 데이터를 줄 때와 똑같은 절차를 밟는다.
- [[LMS-발송-빈도-제한]] ·초안 — 최근 1주일 안에 LMS를 받은 고객은 발송 대상에서 뺀다. 회사 규정이 아니라 팀 내부 기준이다.
- [[LMS-필수-제외자]] ·초안 — LMS에 대해 한 번이라도 문의·불만을 제기한 고객은 "필수 제외자"로 등록해 이후 무조건 발송에서 뺀다.
- [[가명결합정보-사후관리]] ·초안 — 가명정보를 외부에 제공하거나 결합정보를 받아 분석할 때, 제공·수령 이후에 지켜야 하는 관리 규칙 모음. 사용기한과 파기, 결합키 보관, 수령확인서와 홈페이지 게시, 정보계 접근 중지, 재식별 금지를 다룬다.
- [[개발-변경-일정-감안]] ·초안 — 전송 개발은 작은 수정도 정규 이관 절차를 밟으므로, 고객과 일정을 약속할 때 최소 소요기간을 반영한다.
- [[결합-데이터-파기]] ·초안 — 결합에 쓴 원 데이터와 결합 결과는 목적을 달성하면 파기한다. 전문기관은 반출 후 한 달 안에 파기한다.
- [[경쟁점-정보-노출-VOC-주의]] ·초안 — 가맹점주(사장님) 대상 서비스에서 경쟁 매장 정보를 보여주면 VOC가 몰릴 수 있다는, 당사(삼성카드) 경험에서 나온 노하우.
- [[기타정보-명세-관리]] ·초안 — 가명·익명 데이터는 명세가 가·익명 시스템에 남지만, 기타 정보(통계)의 최종 명세는 흩어져 있다. 새로 제공할 때는 시스템에 근거를 남긴다.
- [[데이터-요건-초기-확정]] ·초안 — 데이터 요건은 영업 단계에서 비식별 영향까지 감안해 최대한 확정하고, 이후에 바뀌지 않게 한다.
- [[데이터전문기관-인력-요건]] ·초안 — 데이터 전문기관 라이선스를 유지하려면 전담 인력 2명 이상을 두고, 이들을 원칙적으로 다른 업무에서 분리해야 한다.
- [[비식별-처리-그라운드룰]] ·초안 — 비식별 처리에는 정해진 일률적 규칙이 없고 건별로 협의하지만, 최소한으로 지켜야 하는 기본 기준(그라운드룰) 문서가 있다.
- [[사업-이력-기록]] ·초안 — 업체별 사업 이력은 맥락(왜 시작됐는지, 누가 소개했는지)까지 남긴다. 이 위키의 사업 페이지도 같은 원칙을 따른다.
- [[사용-제한-데이터]] ·초안 — 회사가 가진 데이터라도 모두 팔 수 있는 것은 아니다. 동의 여부, 수집 목적, 법 저촉 여부를 따져야 하며, 아래 데이터는 특히 주의한다.
- [[샘플-데이터-제공-제한]] ·초안 — 계약 전 고객에게 실제 데이터 샘플을 파일로 내보내는 것은 원칙적으로 금지다. 영업에서 가장 자주 부딪히는 약점이다.
- [[시계열-제공-샘플링]] ·초안 — 시계열 데이터나 주기적·반복적으로 제공하는 데이터는 전체를 그대로 내보내지 않고 반드시 샘플링한다.
- [[외부발송-용량과-파일분할]] ·초안 — 데이터를 외부로 보낼 방법과 파일 분할은 [[가익명-시스템]]에 올리기 **전에** 정해야 한다.
- [[적정성-평가-일정-감안]] ·초안 — 가명·익명 데이터의 제공 일정은 월 1회 [[적정성-평가]] 일정에 묶여 있으므로, 고객과 납기를 약속할 때 이를 반영한다.
- [[전결-확인]] ·초안 — 모든 결재에서 [[전결]]을 올리기 전에 반드시 확인한다. 설명자가 가장 먼저, 가장 강하게 강조한 규칙.
- [[접근권한-회수-통보]] ·초안 — 프로젝트가 끝나면 프로젝트 DB 접근 권한을 삭제하고 정보보호 담당에 알린다.
- [[추진품의-사전합의]] ·초안 — [[추진품의]]는 올리기 전에 내용을 관련 담당자와 완전히 합의한 뒤 상신한다.

## 시스템
- [[CB-웹-조회-서비스]] ·초안 — 개인 신용정보는 메일로 보낼 수 없어서 만든 웹 조회 화면. 계약한 고객사가 사업자 정보를 넣으면 CB 정보를 볼 수 있다.
- [[DLS]] ·초안 — 정보계에서 데이터 송신을 담당하는 영역(원문 "데이터 랩 서비스"). API·전송 개발은 이 영역의 담당 개발자가 한다.
- [[Orange]] ·초안 — 가명·익명 처리 등 실제 데이터 작업을 대부분 하는 쿼리 도구 ORANGE. 녹취의 "오렌지"는 이것.
- [[PC-개인정보-검사]] ·초안 — C 드라이브 문서에 개인정보가 들어 있는지 보안 프로그램이 정기 검사한다.
- [[가익명-시스템]] ·초안 — 가명·익명 정보의 외부 반출 이력을 관리하고, 프로젝트별 DB 접근을 통제하는 사내 시스템.
- [[데이터랩]] ·초안 — 데이터솔루션팀이 운영하는 대외 데이터 플랫폼. 지도 기반 생활경제맵과 지수를 보여주며, 사업팀 영업 소개서에도 들어간다.
- [[메타-관리시스템]] ·초안 — 사내 데이터 테이블 정의를 보는 시스템. 팀장 표현으로 "꿀통". 데이터를 만들 때 가장 많이 봐야 한다.
- [[분석-PC]] ·초안 — 정보계 데이터를 다루는 별도 PC. 파이썬으로 바로 붙을 수 없어 대부분 SQL 기반으로 작업한다.
- [[샤크라]] ·초안 — [[가익명-시스템]]의 프로젝트 DB에 접속할 때 반드시 거쳐야 하는 경로. 명칭과 정체는 STT 기준 추정이다. [확인필요]
- [[중앙-저장-장치]] ·초안 — 사내 파일 저장소. 개인함은 약 3GB이고, 팀은 부서함을 쓰지 않는다.
- [[팀-컨플루언스]] ·초안 — 팀 업무 자료와 미팅 이력이 쌓이는 Confluence 공간. 팀장 표현으로 "모든 히스토리가 다 나와 있다". 원문 "컨퍼런스", "컴플", "컨플"은 모두 이것.

## 용어
- [[CB-서비스-5종]] ·초안 — 당사 개인사업자 CB가 제공하는 다섯 가지 서비스. 월 단위 등급과 일 단위 이벤트로 나뉜다.
- [[CB-업-구분]] ·초안 — 신용평가(CB) 업은 2020년 신용정보법 개정 이후 개인 CB, 기업 CB, 개인사업자 CB로 나뉜다. 기업 CB 안에는 다시 세 가지가 있다.
- [[KCB-컨소시엄-매출]] ·초안 — KCB가 카드사 6개사로부터 매출을 모아 다시 나눠주는 컨소시엄 데이터. 당사 추정매출의 원천이다.
- [[LMS-수익-구조]] ·초안 — LMS 1건당 광고 단가에서 대행사 몫과 통신비를 빼면 당사 이익이 약 44원이다.
- [[가명-처리-기법]] ·초안 — 원본 데이터를 알아볼 수 없게 바꾸는 방법들. 결합에서는 원 데이터를 최대한 유지하려 하므로 암호화와 삭제 위주로 쓴다.
- [[가명처리-명세서]] ·초안 — 가명(또는 익명) 처리를 어떻게 했고 결과가 어떤지 보여주는 서류. 결합과 외부 제공 검토에 모두 쓰인다.
- [[개인신용정보-가명-익명-정의]] ·초안 — 개인신용정보·가명정보·익명정보의 법적 정의와 각각 쓸 수 있는 범위. 당사 정보보호팀이 매년 교육하는 기본 개념이다.
- [[건강소비지수]] ·초안 — 카드 소비 패턴으로 건강한 생활습관을 점수화한 지수. 데이터솔루션팀의 대표 임베디드 상품이며 논문까지 냈다.
- [[결합-비용-구조]] ·초안 — 데이터 결합 시 드는 평가 비용과 결합 비용, 그리고 자가결합이 적자가 나는 이유. 녹취 음질 때문에 숫자 일부가 불명확하다.
- [[결합전문기관]] ·초안 — 가명정보끼리 결합하는 일반 기관. 금융회사가 끼는 결합은 여기가 아니라 [[데이터-전문기관]]에서 해야 한다.
- [[데이터사업-매출-구조]] ·초안 — 데이터사업(담당) 매출을 어떻게 나누고, 연도별로 얼마를 했고, 어떤 기준으로 집계하는지. 사실상 **데이터 판매**와 **LMS 광고** 두 축이다.
- [[외국인-데이터]] ·초안 — 외국인 소비 데이터. 해외 발급 카드 매입 데이터와 선불카드(와우패스) 데이터로 구성되며, 수요가 많다.
- [[원본처리자-가명처리자]] ·초안 — 가명·익명 처리 작업에서 원본을 뽑는 사람과 가명(익명) 처리하는 사람을 분리하는 역할 구분.
- [[이행확약서]] ·초안 — 결합 결과를 받은 쪽이 데이터를 어떤 환경에서 누가 쓰고, 언제 파기할지 약속하는 서류.
- [[자가결합]] ·초안 — 당사(삼성카드)가 데이터 전문기관이면서 동시에 결합 당사자인 결합. 당사 전문기관 결합 건의 대부분이 여기에 해당한다.
- [[전결]] ·초안 — 결재 단계마다 누가 승인하고, 누가 결재하고, 누가 통제하며, 누구에게 통보하는지를 정한 권한 체계.
- [[정보-분류]] ·초안 — 외부 제공 데이터를 가명 / 가명결합 / 익명 / 기타 네 가지로 나누는 것. 분류에 따라 이후 프로세스·품의·전결이 모두 달라진다.
- [[추가정보]] ·초안 — 가명정보를 다시 특정 개인과 연결할 수 있게 해주는 정보. 법적 정의에 "매핑 테이블 등"이 들어 있어, 당사는 결합 과정의 중간 산출물까지 추가정보로 본다.
- [[추진품의]] ·초안 — 데이터 제공 사업을 추진하기 위한 품의. 원래 두 품의(추진품의 + 시행품의)를 하나로 합쳐 쓰고 있다.
- [[평가-주기]] ·초안 — 회사의 평가 리듬. 조직·개인은 12~5월, 6~11월로 나뉘고, 임원은 1~10월 실적으로 평가한다. 성과를 언제 내느냐가 중요하다.
- [[해시]] ·초안 — 파일 내용으로 계산한 고유값. 외부 반출 시 "이 파일이 승인된 그 파일인지" 확인하는 데 쓴다.

- [[롯데멤버스-추정매출]] ·초안 — 롯데멤버스가 3개 카드사에서 받던 데이터를 당사 단독으로 바꾼 건. 당사만 가진 추정매출이 결정적 근거였다.

- [[삼성전자-정기-데이터]] ·초안 — 관계사 삼성전자에 정기적으로 데이터를 판매하는 건. 그룹 최고위층 관심에서 시작해 LG유플러스 결합 분석을 거쳐 정기 구매로 이어졌다.
- [[신세계-가명정보-제공]] ·초안 — 신세계에 가명정보를 결합전문기관 없이 매월 직접 제공하는 사업. 가명 직접 제공은 현재 이 건과 [[나이스지니데이타-가명정보-제공]] 두 건뿐이다.
- [[아모레퍼시픽-정기-결합]] ·초안 — 아모레퍼시픽과 반기마다(연 2회) 반복하는 가명정보 결합 사업.
- [[이마트24-정기-결합]] ·초안 — 이마트24와 분기마다 반복하는 가명정보 결합 사업. 당사 데이터 전문기관에서 [[자가결합]]으로 진행.
- [[인하대-프로젝트]] ·초안 — 조윤성이 맡게 될 스팟성 데이터 제공 건. 반출 절차 설명의 예시로 쓰였다.
- [[지마켓-온라인쇼핑지수]] ·초안 — 임베디드 상품의 첫 판매 사례. 고객 동의 기반으로 타 온라인 쇼핑몰 이용 금액을 그룹핑한 '온라인 쇼핑 지수'를 제공한다.
